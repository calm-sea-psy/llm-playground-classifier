# 문서 전산화 (설치판)

[README](../README.md) · [구조](architecture.md) · [팩 측정 보고서](pack_reports.md) · [설치 파일 만들기](../installer/README.md)

이력서 · 영수증을 **이 PC 안에서만** 읽어 필드를 추출하고, 사람이 검수한 뒤 엑셀로 내보내는 Windows 프로그램입니다. 평가 도구에서 측정해 합격한 문서 종류만 들어 있고, 추출 · 검증 코드는 평가 도구와 같습니다 ("측정한 코드 = 배포하는 코드").

| 문서 종류 | 판정 | 조건 |
|---|---|---|
| 영수증 | 합격 | 검증을 통과한 문서는 검수 없이 내보낼 수 있음 |
| 이력서 | **조건부 합격** | 검증을 끄지 않음 · **모든 문서를 사람이 검수** (검증을 통과해도 자동 승인하지 않음) |

판정 근거: [팩 측정 보고서](pack_reports.md)

**설치판 결과 = 측정한 결과 (2026-09-27 대조, `eval/digitizer/AppParity`)**: 설치판에 문서를 올려 대기열로 처리한 결과를 평가 도구 측정과 비교했습니다.

| 문서 | 원문 | 필드 | 검증 오류 수 | 이미지 재확인 |
|---|---|---|---|---|
| 이력서 보류 세트 16장 × PDF · DOCX · 스캔 (48건) | 48/48 같음 | 48/48 같음 | 48/48 같음 | - |
| 영수증 KORIE 30장 | 30/30 같음 | 24/30 같음 | 30/30 같음 | 30/30 같음 |

영수증 필드 6장의 차이(상호 · 단가 한두 칸)는 LLM 의 흔들림 범위입니다: 평가 도구를 같은 설정으로 두 번 돌려도 30장 중 7장에서 필드가 달라졌고, 흔들리는 칸도 같았습니다.

## 필요한 사양

| | 권장 | 최소 |
|---|---|---|
| Windows | 11 · 10 (1809 이상), 64비트 | |
| GPU | NVIDIA, 메모리 8GB 이상 (드라이버가 CUDA 12.9 이상 지원) | 없어도 됨 (CPU 로 처리, 느림) |
| 메모리 | 16GB 이상 | 8GB |
| 디스크 | 여유 15GB | 여유 9GB (GPU 없는 구성) |
| 인터넷 | 설치할 때만 (모델 · OCR 내려받기) | |

- 처리 속도: NVIDIA GPU 16GB 에서 문서당 약 11~20초. GPU 가 없으면 [아래](#gpu-없는-pc) 를 보세요.
- 관리자 권한 없이 설치합니다. GPU 도 관리자 권한 없이 씁니다 (드라이버 설치 · 업데이트에만 관리자 권한이 필요).

## 설치

1. `DocumentDigitizer-setup-<버전>.exe` 를 실행합니다 (약 70MB).
   - "Windows의 PC 보호" 창이 뜨면 **추가 정보 ➔ 실행**. 코드 서명을 하지 않은 설치 파일이라 뜹니다. 공식 배포처(GitHub Releases)에서 받은 파일이 아니면 실행하지 마세요.
2. 설치 전 안내(받는 양 · 개인정보)를 읽고 진행합니다. 프로그램은 `%LocalAppData%\Programs\DocumentDigitizer` 에 설치됩니다.
3. 파일을 놓은 뒤 **설치 도우미**(콘솔 창)가 이어서 실행됩니다.
   - 사양을 보고 구성을 고릅니다: GPU 8GB 이상 = gemma4:12b + GPU OCR / 8GB 미만 = gemma-4-E4B + GPU OCR / GPU 없음 = gemma-4-E4B + CPU OCR
   - 받는 양 · 시간을 보여 주고 계속할지 묻습니다. GPU 8GB 이상 구성은 최대 약 11GB (100Mbps 에서 약 15~20분)
   - Ollama (없을 때만, 설치 전에 물어봄) ➔ 모델 ➔ OCR(Python 3.11 + PaddleOCR) ➔ 설정 ➔ 로그인 시 자동 시작
   - 단계가 실패하면 **다시 시도 · 건너뛰기 · 끝내기** 를 고릅니다. 끝나지 않은 단계는 나중에 시작 메뉴 **문서 전산화 설치 도우미** 로 다시 실행하면 됩니다 (이미 된 단계는 건너뜀)
   - NVIDIA 드라이버가 오래됐거나 확인이 안 되면 알려 주고 **드라이버 업데이트 후 다시 · CPU 로 설치 · 그래도 GPU** 중에서 고르게 합니다
4. 마치면 프로그램이 실행되고 브라우저에 화면(http://127.0.0.1:5310)이 열립니다.

## 사용

프로그램은 알림 영역(시계 옆, 숨겨진 아이콘 ^ 안)에 상주합니다. 아이콘을 두 번 누르거나 시작 메뉴 **문서 전산화** 를 누르면 화면이 열립니다.

### 문서 넣기

- **폴더에 넣기**: `문서\문서 전산화\넣기\영수증` · `넣기\이력서` 에 파일을 넣으면 자동으로 접수됩니다. 복사가 끝나고 몇 초 뒤에 가져갑니다.
- **화면에서 올리기**: [올리기] 에서 종류를 고르고 파일을 끌어다 놓습니다. 폴더에 넣는 것과 같은 대기열입니다.
- 받는 형식: PDF · DOCX · 이미지(PNG · JPG · TIF · BMP), 파일당 50MB. 여러 쪽 스캔은 한 PDF 로 묶어 넣습니다.
- 같은 종류로 같은 내용을 두 번 넣으면 두 번째는 처리하지 않고 `실패` 폴더로 옮깁니다 (사유 파일 포함).

### 처리 결과와 폴더

| 결과 | 화면 상태 | 원본이 옮겨지는 곳 |
|---|---|---|
| 검증 통과 (영수증) | 검증 통과 | `처리됨\영수증\<날짜>` |
| 검증 문제 · 종류 의심 · 이력서 전부 | 확인 필요 | `확인 필요\<종류>` |
| 원문 추출 · LLM 실패, 지원하지 않는 형식, 중복 | 실패 · 중복 | `실패` (+ `<파일 이름>.실패 사유.txt`) |
| 검수에서 승인 | 승인 | `처리됨\<종류>\<날짜>` |
| 검수에서 반려 | 반려 | `실패` (+ 반려 사유) |

- 확인 필요 건이 늘면 알림 영역에 알림이 뜨고, 화면 위쪽 **문서** 탭에 건수가 보입니다.
- 필수 항목이 대부분 비어 있으면 "이 폴더(문서 종류)가 맞는지 확인" 경고가 붙습니다 (예: 이력서 폴더에 영수증).

### 검수

목록에서 문서를 누르면 왼쪽에 원본(이미지 · PDF) 또는 원문 텍스트, 오른쪽에 추출한 필드가 나옵니다.

- 검증에 걸린 칸은 빨갛게 표시되고 이유가 나옵니다. 값을 고치면 "고침" 표시가 붙습니다.
- **다시 검사**: 고친 값을 팩 규칙으로 다시 검사합니다. 원본을 보고 고친 값이 OCR 원문과 달라 생기는 "원문에 없음" 은 경고로만 나옵니다.
- **승인**: 검증 문제가 남아 있으면 "원본과 대조해 확인했습니다" 를 체크해야 승인됩니다. 승인하면 같은 종류의 다음 확인 필요 문서로 넘어갑니다.
- **반려**: 사유를 적어야 합니다 (예: 다른 종류 문서, 원본이 흐려 읽을 수 없음).
- 목록 항목(학력 · 경력 · 품목 등)은 추가 · 삭제할 수 있습니다.

### 엑셀 내보내기

[내보내기] 에서 종류별로 **새 문서 내보내기** 를 누릅니다. 대상은 승인한 문서와, 합격 종류(영수증)에서 검증을 통과한 문서입니다. 이력서는 승인한 문서만 나갑니다.

- 시트 구성은 팩에 정해져 있습니다 (이력서: 인적사항 · 학력 · 경력 · 자격증 · 어학 / 영수증: 영수증 · 품목). 검수에서 고친 값이 들어갑니다.
- 파일은 내려받기와 함께 `문서\문서 전산화\내보내기` 에도 남습니다. 이미 내보낸 문서는 다음에 빠지고, **전체 다시** 로 다시 넣을 수 있습니다.
- 내보내기 폴더의 엑셀은 **엑셀 보관 기한**(기본 90일)이 지나면 지웁니다. 내보낸 기록에는 "보관 기한이 지나 지움" 으로 남습니다. 다른 곳에 넘길 파일은 기한 안에 옮겨 두세요.

### 그 밖의 화면

- **수정률**: 승인한 문서에서 검수 때 고친 칸의 비율입니다. 운영 중 정확도로 볼 수 있습니다.
- **설정**: 모델 · 문서 폴더 · 보관 기한 · 엑셀 보관 기한 · 로그인 시 자동 시작. 측정한 모델이 아니면 경고합니다. 나머지 처리 설정은 측정한 값입니다.
- **상태 점검**: Ollama · 모델 · OCR 서비스 · GPU · 디스크 상태와 해결 방법.
- **일시 정지**: 알림 영역 메뉴에서 처리를 멈춥니다. 새 문서는 접수만 되고, 다시 시작하면 이어서 처리합니다.

## GPU 없는 PC

설치 도우미가 GPU 를 찾지 못하면 gemma-4-E4B 모델과 CPU OCR 로 설치합니다. 결과 품질은 측정한 범위 안이지만 느립니다.

| 입력 (합성 이력서 보류 세트 16장) | 문서당 중앙 | 최대 | 120초 넘음 |
|---|---|---|---|
| PDF · DOCX (OCR 없음) | 30초 | 54초 | 0 |
| 스캔 이미지 (CPU OCR) | 66초 | 126초 | 2 (둘 다 2쪽 스캔) |

- 측정: 이 설치판을 GPU 를 쓰지 않는 설정(gemma-4-E4B CPU + CPU OCR)으로 돌림, CPU 는 AMD Ryzen AI 9 HX 370 (노트북, 12코어) (2026-09-27). CPU 가 느린 PC 는 더 걸립니다.
- 추출 결과는 GPU 없이 잰 측정(0단계)과 원문 · 필드 · 검증까지 16장 모두 같았습니다.
- 처리는 한 번에 한 건씩이라, 많이 넣어 두면 쌓인 순서대로 처리합니다.

## 개인정보

- 문서 원본 · 원문 · 추출 값은 **이 PC 에만** 저장됩니다. LLM 과 OCR 도 이 PC 에서 실행되며 인터넷으로 문서를 보내지 않습니다.
- **보관 기한**(기본 90일, 접수한 때 기준)이 되면 원본 파일과 원문을 지웁니다. 내보낸 적 없는 문서는 기록도 지우고, 내보낸 문서는 "언제 무엇을 내보냈는지" 만 남깁니다.

  | 설정 | 설정 파일 (`%LocalAppData%\Digitizer\settings.json`) | 기준 | `0` | `1` |
  |---|---|---|---|---|
  | 보관 기한 (원본 · 원문 · 기록) | `RetentionDays` | 접수한 때 | 지우지 않음 (개인정보가 계속 남음) | 1일(24시간)이 되면 |
  | 엑셀 보관 기한 | `ExportRetentionDays` | 내보낸 때 | 지우지 않음 | 1일(24시간)이 되면 |

  둘 다 기본 90일이고, 설정 화면에서도 바꿉니다 (설정 파일을 직접 고쳤으면 프로그램을 다시 시작). 1시간마다 확인하므로 기한이 된 뒤 1시간 안에 지워집니다. 열려 있는 파일은 닫은 뒤 다음 확인 때 지웁니다.
- 화면은 이 PC 에서만 열립니다 (127.0.0.1, 다른 사이트에서 보내는 요청은 거부).
- 로그 파일에는 파일 이름 · 전화번호 · 이메일 · 주민등록번호를 남기지 않습니다.
- 이력서의 수집 금지 항목(주민등록번호 · 가족 · 혼인 · 신체 · 출신 지역)은 추출하지 않습니다. 원문 텍스트의 주민등록번호는 검수 화면에서 가려 보여 줍니다. **원본 이미지 위에서는 가리지 않습니다** (한계).

## 문제 해결

| 증상 | 해결 |
|---|---|
| 이미지 · 스캔 PDF 가 모두 "원문 추출 실패" | 상태 점검에서 OCR 서비스 확인 ➔ 프로그램을 다시 시작. 계속되면 설치 도우미를 다시 실행 (`logs\ocr-날짜.log` 에 원인) |
| "LLM 추출 실패 … 연결하지 못했습니다" | Ollama 가 꺼져 있음. 시작 메뉴에서 Ollama 실행 (프로그램도 시작할 때 실행을 시도함) |
| 상태 점검에서 모델 없음 | 명령 창에서 `ollama pull <모델>` 또는 설치 도우미 다시 실행 |
| GPU 가 있는데 CPU 로 설치됨 | NVIDIA 드라이버 확인 후 설치 도우미를 다시 실행 (필요하면 `setup-helper.cmd -Mode gpu`) |
| 문서가 계속 "대기" | 알림 영역 메뉴 또는 화면 위쪽 띠에서 **다시 시작** (일시 정지 상태) |
| 폴더에 넣었는데 접수되지 않음 | 다른 프로그램이 파일을 열고 있거나 아직 복사 중. 임시 파일(~$ · .tmp · .crdownload)은 무시합니다 |
| 화면이 열리지 않음 | 알림 영역 아이콘 확인. 없으면 시작 메뉴 **문서 전산화** 실행 (이미 실행 중이면 화면만 열림) |

## 제거

Windows **설정 ➔ 앱** 에서 **문서 전산화** 를 제거합니다. 실행 중이면 끄고 진행합니다.

- 프로그램 폴더(OCR 환경 · Python · OCR 모델 포함)와 자동 시작 등록을 지웁니다.
- 처리 기록 · 설정 · 로그를 지울지 묻습니다. 다시 설치해서 이어 쓰려면 **아니요**.
- 문서 폴더(`문서\문서 전산화`)의 원본 · 엑셀 파일은 지우지 않습니다.
- Ollama 와 LLM 모델은 다른 프로그램도 쓸 수 있어 지우지 않습니다. 필요 없으면 Ollama 를 따로 제거하세요.

## 한계

- 이력서는 조건부 합격입니다. 검수 없이 쓰면 안 됩니다 ([조건](pack_reports.md)).
- 합성 이력서와 공개 영수증 데이터(KORIE)로 측정했습니다. 실제 문서는 양식이 더 다양하므로, 수정률 화면으로 운영 중 정확도를 계속 보세요.
- 원본 이미지 위의 수집 금지 값은 가리지 않습니다.
- 한 PC · 한 사용자용입니다 (로그인 · 여러 사용자 · 네트워크 공유 없음).
