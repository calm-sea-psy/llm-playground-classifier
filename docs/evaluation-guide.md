## 평가 절차

1. **샘플 준비**: 실제 업무 문서(또는 X-ray) 30~150장. 정답이 있으면 정확도까지, 없으면 검증 통과율과 속도로 비교합니다.
2. **실험**: "모델 비교" 화면에서 조합(모델, OCR 경로, VLM 폴백 등)을 최대 4개 정해 실행합니다.
3. **결과 해석**: 조합별 점수와 함께 **사람이 확인해야 하는 비율**과 **틀렸는데 통과한 건수**를 봅니다. 문서별 표에서 조합마다 결과가 다른 문서를 열어 원인을 확인합니다.
4. **오답 분류**: 틀린 이유를 나눕니다.
   - OCR이 잘못 읽음: 전처리나 규칙으로 보정
   - 용어·정의를 모름: 필드 정의나 용어집(RAG) 추가
   - 규칙을 알려 줘도 어김: 모델 교체, 그래도 안 되면 파인튜닝 검토
   - 정답 기준이 다름: 명세를 결정
5. **개선과 재실험**: "프롬프트" 화면에서 지시문이나 용어집을 고쳐 새 버전으로 적용한 뒤 같은 샘플로 다시 실험합니다. 작업마다 쓴 프롬프트 버전이 기록됩니다.
6. **적용**: 가장 나은 조합을 **[기본으로 적용]** 해서 실제 처리 화면의 기본 설정으로 씁니다.

자기 회사 문서로 평가할 때 정답 데이터를 준비하는 방법은 [설치와 실행 ➔ 7. 정답 데이터](installation.md#7-선택-정답-데이터)에 있습니다.

## 평가 스크립트 (`eval/`)

화면보다 큰 규모로 돌리거나 한 단계만 따로 측정할 때 씁니다. 결과는 `eval/results/{실행 이름}/` 에 저장되고 git에서 제외됩니다. 파이썬은 OCR 서비스의 가상 환경(`src/OcrService/.venv/Scripts/python`)으로 실행합니다. CNN 관련 스크립트는 CNN 서비스의 가상 환경을 씁니다.

| 스크립트 | 하는 일 |
|---|---|
| `run_eval.py` ➔ `score_eval.py` | 문서 N장을 모델별로 API에 보내 처리하고 채점합니다. 필드·금액 정확도, 품목 F1, 지어낸 금액, 검증 통과율, 시간을 CSV와 summary.md로 남깁니다 |
| `score_ocr.py`, `ocr_variants.py`, `score_aihub.py` | OCR 엔진과 옵션을 비교합니다 (언어, 문서 펴기, 경로 A/B) |
| `fallback_threshold.py` | VLM 폴백 신뢰도 기준값을 정합니다 |
| `cnn_eval.py`, `cnn_models.py`, `cnn_models_mm.py` | CNN 후보(사전학습 vs 미세조정)를 AUC, 민감도, 특이도로 비교합니다 |
| `multimodal_eval.py` | X-ray + 소견서 통합 작업을 모델별로 돌려 소견서 요약 F1, CNN AUC, VLM 정확도, 통합 검출률을 계산합니다 |
| `summary_variants.py` | 소견서 요약 프롬프트 변형(기본 / RAG / 예시 / 둘 다)을 개발 세트와 보류 세트로 비교하고, 바뀐 판단을 목록으로 보여 줍니다 (`--diff`) |
