# RAG vs 파인튜닝 결론 리포트 (1차 문서 OCR + 2차 흉부 X-ray)

- 작성: 2026-09-25
- 대상 모델: `gemma4:12b` (기본), 비교 `qwen3-vl:8b` / `qwen3-vl:8b-instruct`, Ollama 0.34.3, RTX 5080 16GB
- **결론: LLM(텍스트) 쪽은 파인튜닝하지 않는다. 용어·필드 정의를 넣는 RAG + 코드 검증 + 사람 확인으로 간다.**
  **파인튜닝이 값을 하는 곳은 "영상을 보는 눈"(CNN/VLM) 쪽이며, 이미 소아 폐렴 CNN 에 적용했다.**

> 용어: 이 리포트의 "RAG" 는 임베딩 검색이 아니라 **키워드(정규식) 트리거 용어집**입니다. 소견서에 나온 용어의 정의만 찾아 붙이는, RAG 의 가장 단순한 형태입니다. 결정적이고(같은 입력엔 같은 정의), 작업마다 붙인 정의가 기록되며, 벡터 DB 가 필요 없습니다.

## 1. 판단 기준

todo 4번 ㅂ)에서 정한 기준을 그대로 썼다.

| 오답 유형 | 뜻 | 처방 |
|---|---|---|
| **몰라서** | 문서 형식·용어·필드 정의를 모름 | RAG (참조 문서·정의·예시 제공) |
| **규칙을 못 따라서** | 알려 줘도 출력 형식·추출 규칙을 어김 | 파인튜닝 검토 |
| (추가) **입력이 틀려서** | OCR 오인식 등 LLM 앞단 오류 | 규칙·전처리 (LLM 문제 아님) |
| (추가) **정답 정의가 달라서** | 모델 판단은 합리적인데 라벨 기준이 다름 | 명세 결정 (어느 쪽으로 할지 사람이 정함) |
| (추가) **못 봐서** | 영상에서 소견을 인식 못 함 | 영상 모델 파인튜닝 |

## 2. 1차 (영수증 필드 추출) 오답 분류

근거: `docs/model_selection.md`, develop.md B 단계 (KORIE 150장)

| 오답 | 유형 | 한 조치 | 결과 |
|---|---|---|---|
| 수량 1 ➔ 7 (PaddleOCR 오인식) | 입력이 틀려서 | C# 보정 규칙 (금액 = 단가면 수량 1) | 수량 정확도 qwen 90.6 ➔ 96.2% |
| 합계 = 결제 금액 vs 할인 전 합계 | 정답 정의가 달라서 / 몰라서 | `gross_total` 필드 추가, 정의 명시 | 합계 93.0 ➔ 96.5% |
| 거래 시각·상호·영수증 번호·소계 | 정답 정의가 달라서 | (라벨 모호, 수치 해석 시 감안) | — |
| qwen 금액 지어내기 (수량×단가) | 규칙을 못 따라서 | 모델별 프롬프트 (금지 + 올바른/잘못된 예) | 11 ➔ 5건 (남음) |
| qwen 합계를 소계에 복사 | 규칙을 못 따라서 | 프롬프트 지시 | **효과 없음** (54.8 ➔ 53.2%) |
| 반복 생성으로 잘림 | 규칙을 못 따라서 (형식) | `num_predict` 4096 상한 + 스키마 오류 처리 | 작업 실패 ➔ 해당 시도만 실패 |

- gemma4 는 "규칙을 못 따라서" 유형이 거의 없다 (지어낸 금액 1건, JSON 스키마 100%, 검증 통과 92.7%)
- 프롬프트로 안 고쳐지는 규칙 위반은 **qwen 에만** 남았고, 이는 파인튜닝보다 **모델 선택**(gemma4)으로 해결됨

## 3. 2차 (소견서 요약) 실험: RAG vs 예시

2차-5 오답(폐부종 거짓 양성 8건 등)을 유형별로 나눠, 소견서 요약 단계만 프롬프트를 바꿔 다시 돌렸다.
`eval/summary_variants.py` — Ollama 직접 호출, API 와 같은 프롬프트·스키마·옵션 (temperature 0)

| 변형 | 넣은 것 | 겨냥한 유형 |
|---|---|---|
| base | 현재 프롬프트 | — |
| rag | 소견서에 나온 용어의 **정의**를 용어집(10항목)에서 키워드로 찾아 붙임 | 몰라서 |
| fewshot | 부정·의심 표현 판단 **예시** 4개 (용어 정의 없음) | 규칙을 못 따라서 |
| both | rag + fewshot | 둘 다 |

- **dev**: 2차-5 의 120건. 용어집을 이 세트 오답을 보고 만들었으므로 낙관적
- **test**: 겹치지 않는 새 120건 (정상 30 + 폐부종 20 + 울혈만 10 + 그 밖의 이상 60). **결론은 이 세트로 판단**

**결과 (소견별 F1, 괄호는 거짓 양성/놓침)**

| 세트 | 변형 | 형식 성공 | 폐렴 | 심장비대 | 흉수 | 무기폐 | 폐부종 | 오답 합 |
|---|---|---|---|---|---|---|---|---|
| dev | base | 118/120 | 89% (4/1) | 97% (2/0) | 94% (2/0) | 97% (2/0) | 20% (8/0) | 19 |
| dev | rag | 119/120 | 92% (4/0) | 98% (1/0) | 94% (2/0) | 97% (2/0) | 57% (3/0) | **12** |
| dev | fewshot | 118/120 | 89% (4/1) | 97% (2/0) | 93% (2/0) | 97% (2/0) | 40% (3/0) | 14 |
| dev | both | 120/120 | 88% (6/0) | 98% (1/0) | 94% (2/0) | 97% (2/0) | 57% (3/0) | 14 |
| **test** | base | 117/120 | 77% (5/4) | 100% (0/0) | 89% (4/1) | 97% (1/1) | 83% (7/1) | 24 |
| **test** | rag | **120/120** | 80% (10/0) | 100% (0/0) | 91% (4/0) | 97% (1/1) | 88% (4/1) | 21 |
| **test** | fewshot | 119/120 | 72% (10/3) | 99% (1/0) | 91% (3/1) | 97% (1/1) | 86% (5/1) | **26** |
| **test** | both | 119/120 | 83% (8/0) | 99% (1/0) | 89% (4/1) | 97% (1/1) | 90% (3/1) | **20** |

양성 수: dev 폐렴 22·심장비대 30·흉수 15·무기폐 32·폐부종 2 / test 20·48·21·33·20. 처리 시간은 모두 약 5초 (용어집을 붙여도 차이 없음)

**해석**
- **용어 정의(RAG)는 새 세트에서도 통했다**: "pulmonary vascular congestion ➔ 폐부종 아님"이 test 의 울혈 3건을 고침 (폐부종 거짓 양성 7 ➔ 4), 폐렴 놓침 4 ➔ 0 ("infiltrate ➔ 폐렴"), 형식 실패 3 ➔ 0
- **예시(fewshot)는 dev 에서만 좋았다**: dev 19 ➔ 14 였지만 test 24 ➔ 26 (악화). 특히 uid 3241 "No focal airspace consolidation" 을 예시 2번이 거의 같은 문장으로 "false" 라고 보여 주는데도 폐렴 true 로 표시 ➔ **부정문 규칙 위반은 예시로 고쳐지지 않았다**
- **RAG 의 부작용**: "airspace·infiltrate ➔ 폐렴" 정의가 폐렴 거짓 양성을 5 ➔ 10 으로 늘림. 대부분은 아래 "정답 정의가 달라서" 유형

**가장 좋은 변형(test/both)에 남은 오답 21건 분류** (소견서 원문을 한 건씩 확인)

| 유형 | 건수 | 예 |
|---|---|---|
| 정답 정의가 달라서 — 의심·감별 표현 | 11 | "question small effusions", "differential includes infectious", "may be … infiltrates or edema" ➔ 프롬프트 규칙("의심은 true")대로 true, IU MeSH 는 확정 소견만 태깅 |
| 정답 정의가 달라서 — 라벨 누락·오류 | 4 | "suggesting mild interstitial pulmonary edema" 인데 MeSH 에 폐부종 없음, "small left basilar scar" 인데 MeSH 는 무기폐 |
| 정답 정의가 달라서 — 용어 매핑 차이 | 3 | "alveolar consolidations"·"airspace opacity" ➔ 규칙상 폐렴 true, MeSH 는 Consolidation·Opacity(폐렴 아님). "costophrenic blunting" ➔ 흉수 |
| **규칙을 못 따라서** | 2 | "No significant change in … pleural fluid" 를 부정으로 읽음 (흉수 있음), 소견서에 없는 심장비대를 true |
| **형식** (잘림) | 1 | 스키마에 없는 키를 지어내며 반복 ➔ 4096 토큰 |

➔ 남은 오답의 **약 85%(18/21)가 정답 기준 차이**(그중 절반 이상이 "의심을 양성으로 볼 것인가")이고, 모델이 규칙을 못 따른 것은 **120건 중 3건(2.5%)**

## 4. 2차 (영상) 오답: "못 봐서"

- VLM 독립 판독: 폐렴 민감도 77% / 특이도 62% (gemma4), 이상 여부 민감도 69% (2차-5)
- 영상 인식 오류는 텍스트 정의를 줘도 고쳐지지 않는다 (VLM 에 CNN 결과를 보여 주면 오히려 따라가서 오답을 못 잡음, 2차-3b)
- 이미 한 파인튜닝: 소아 폐렴 CNN — 사전학습 xrv 대비 파인튜닝 ResNet 이 확실히 좋아서 채택 (2차-1b). 성인 소견은 사전학습(xrv-all)이 파인튜닝보다 나아서 유지
- 통합에서 CNN 오답은 **소견서와의 불일치**가 가장 잘 잡는다 (폐렴 25/30, 2차-5) ➔ 영상 모델을 더 키우기보다 소견서·사람 확인과 묶는 것이 현재 규모에서 효과적

## 5. 결론

| 영역 | 결론 | 이유 |
|---|---|---|
| 문서 필드 추출 (1차) | **파인튜닝 안 함** — 필드 정의 명시(RAG/프롬프트) + C# 검증 + VLM 폴백 | gemma4 의 규칙 위반은 거의 없음. 남은 오류는 OCR 입력·라벨 정의. 규칙을 못 따르는 qwen 은 모델 선택으로 해결 |
| 소견서 요약 (2차) | **RAG (용어집) 채택 권장**, 예시는 넣지 않음 | 새 세트에서 오답 24 ➔ 21, 형식 실패 3 ➔ 0. 예시는 일반화 안 됨. 남은 오답 대부분은 명세 결정 문제 |
| 영상 판독 (2차) | **영상 모델 쪽 파인튜닝** (소아 CNN 적용 완료), VLM 파인튜닝은 데이터 확보 후 | 오류 원인이 "못 봐서". 텍스트로는 고쳐지지 않음 |

**LLM 파인튜닝을 하지 않는 이유 (정리)**
1. 규칙 위반 비율이 낮다: 소견서 2.5%, 영수증(gemma4) 지어낸 금액 1/150 — 코드 검증과 사람 확인으로 충분히 잡힘
2. 남은 오답의 대부분은 정답 기준 차이 ➔ 파인튜닝하면 **라벨 기준을 모델에 굳히게** 되고, 기준을 바꿀 때마다 재학습이 필요. 용어집·프롬프트는 파일 수정으로 끝남
3. 비용: 12B QLoRA 는 16GB 한 장에서 가능하지만 학습 데이터(정답 라벨) 수백~수천 건, 모델 버전이 바뀔 때마다 재학습·재평가 필요. 이번 실험의 RAG 는 용어집 10항목, 코드 수십 줄
4. 형식 실패(잘림)는 파인튜닝 없이도 줄었다 (RAG 로 3 ➔ 0) — 남으면 재시도 1회로 대응 가능

**다시 검토할 조건** (파인튜닝 재검토 신호)
- 정의를 알려 줘도 같은 규칙 위반이 5% 이상 반복될 때 (예: 부정문 오독이 누적)
- 문서 종류가 늘어 용어집·예시가 컨텍스트에 다 안 들어갈 때 (그 전에 진짜 검색형 RAG — 임베딩 검색 — 로 전환)
- 응답 속도를 위해 작은 모델(3~4B)로 내려야 할 때 (작은 모델은 규칙 준수가 약할 가능성)

## 6. 권고 (적용은 사용자가 결정)

1. `summarize.system.md` 에 용어집(rag 변형) 적용 — 운영 반영 시 용어집은 별도 파일로 두고 키워드 검색은 C# 에서
2. "의심·감별 표현을 양성으로 볼지" 명세 결정. 지금 규칙(의심 = true)은 **놓치지 않는 쪽**(선별 목적)이라 유지 권장. 평가 시에는 IU 라벨이 확정 소견 기준임을 감안
3. 요약 형식 실패(잘림) 시 1회 재시도 (현재는 바로 사람 확인)

## 한계

- 표본: 세트당 120건, 한 병원(IU) 데이터, 정답이 소견서에서 자동 추출한 MeSH (의심 표현 처리 기준이 불명확)
- 용어집은 dev 오답을 보고 작성 ➔ dev 수치는 낙관적. test 는 한 번만 측정 (용어집을 test 로 고치지 않음)
- 모델은 gemma4:12b 만 측정. qwen instruct 는 폐렴 재현율이 낮았음(2차-5)
- 이번 RAG 는 키워드 검색 + 고정 용어집 (가장 단순한 형태). 임베딩 검색·외부 의학 문서는 쓰지 않음

## 후속 (2026-09-25): 실행 간 흔들림

이 리포트를 쓴 뒤, temperature 0 이어도 Ollama 결과가 호출마다 조금 달라진다는 것을 확인했습니다. 같은 설정(용어집 v0)을 test 세트에서 두 번 돌리면 600칸 중 2칸이 바뀌어 오답이 21 vs 19 로 달라집니다. 따라서 위 표에서 **2건 이내의 차이(예: 용어집 21 vs 둘 다 20)는 흔들림 범위**이고, 결론을 바꿀 만한 차이는 예시(few-shot)의 악화(26)와 형식 실패 감소(3 ➔ 0) 정도입니다. 용어집 v1·v2 실험과 흔들림 측정은 [평가 가이드](evaluation-guide.md#사례-프롬프트-버전으로-고치려다-흔들림을-발견-2026-09-25)에 있습니다.
